## Execution rules (agentic-plan-uitvoering, decided 2026-10-04)

**Tier C for this project (never blind-delegated)**: the invariants of constitution principles VI, VII and VIII, per `docs/agile/working-agreement.md`. Existing: `src/scan/run-tool.ts`, `process-runner.ts`, `env.ts`, `status.ts`, `lifecycle.ts`, `source-probe.ts`, `safe-walk.ts`, `src/evidence/*`, `src/workflows/index.ts`, `src/scan/activities.ts`, `src/report/outcome-block.ts`, `src/cli/verify-evidence.ts`. Reason: whether it is right is a judgment about a security or integrity guarantee, not only a test result. Every Tier C implementation or gate task names its mutation requirement and the mutation loop runs on each; Tier C spikes and review tasks have no mutation loop (their exit criterion or triage is the proof).

**Routing**:

| Tier | Mechanism | Rule |
|------|-----------|------|
| A mechanical | opencode (Qwen via `/opencode-orchestratie`, strictly serial, with timeout) or a Sonnet subagent | opencode never commits; the orchestrator commits as vannifr |
| B judgment inside a fixed design | opencode with the strongest available model, or a Claude Sonnet subagent when opencode quota is short | one task at a time, own diff read before commit |
| C high stakes | Claude Opus designs or executes; independent review by a second pass of another model family | read the whole changed file; confirm the invariant, not only the tests; mutation loop |

**Verification for every task**: read the actual diff (not the executor's report), run `npm run verify` locally, check for silent escape normalization, push, and check the real pipeline (`woodpecker` repo 25) before the next task. A commit message names the model that produced the change. Rows marked gate in the plan also run `npm run test:isolation` locally. Tasks that change behavior update README, AGENTS.md, CHANGELOG or the roadmap in the same commit.

**Superseded tests**: tests that encode old behavior (for example `cleanupRun`, the `TEMPORAL_ADDRESS` default, the plain-runner wiring) are replaced in the same commit as the change they conflict with, marked `superseded by FR-xxx` in the commit body. No adapters with the old signature.

**Hermetic versus isolation**: scenarios without the `@isolation` tag run in `npm run test:bdd:005`, which is part of `verify:full` and CI. Scenarios with `@isolation` run only in the local `test:isolation` gate that `release:gate` requires. CI (Woodpecker, unprivileged Docker steps) cannot prove kernel containment; see the Delivery note.

## Delivery note: what CI proves and what it does not

- **CI proves (hermetic)**: argument construction, path translation, restriction observation, level computation, status precedence, teardown and wiring logic against recorded fixtures with a fake runner; workflow ordering with mocked `@temporalio/workflow`; manifest, verification and report logic; PKI and mTLS handshakes with `node:tls`; architecture tests (no process spawn outside the runners, registry wiring, no `import *`); the static checks on the attack-fixture list and on committed configuration; hermetic cucumber scenarios (no `@isolation` tag); the global and per-glob coverage thresholds.
- **CI does not prove**: kernel containment, that the runtime really applies the restrictions, that a limit really ends a hog, no network from a scan container, SELinux label separation, a real Temporal server refusing unauthenticated clients, a real worker listing only its registry, demo recall and dogfood under isolation. Woodpecker's unprivileged Docker steps cannot run nested rootless containers (measured, R16). These are proven only by the local `npm run release:gate` (the `@isolation` scenarios, `test:isolation`, demo, dogfood), which must be green before a release tag. CI prints `Containment: local release gate only, not proven in CI` in every run summary and the README lists it under Known deviations; a green CI run is therefore never a claim of containment.
- **Residual limits stated in the report**: shared kernel, local signing key, host-side readers parse hostile data, egress during fetch, rootful docker fallback is `partial`, observation of blocked attempts is heuristic where marked.
